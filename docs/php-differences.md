# Differences from PHP

Go matches the PHP library byte for byte, except for the behaviour below. Each row is a change on purpose.

| Behaviour | PHP 5.x | Go | Issue |
|:--- |:--- |:--- |:--- |
| `rgba()` alpha beyond the int range, such as `rgba(1,2,3,9223372036854775808)` | the int cast overflows and gives `#0102038000000000000000` ([subtitle-toolbox-php#1054](https://github.com/yama6a/subtitle-toolbox-php/issues/1054)) | not a color: an alpha above 255 gives false | #11 |
| word timestamp of 2562047 hours or more, such as `<2562047:00:00.000>` | reads it as 9223369200 s | not a time, because `time.Duration` cannot hold it: `WordTimestamp` gives false and `MapWordTimestamps` keeps the tag as written | #11 |
| `EmbedRightToLeft` of a line that ends with LF | the `$` of its pattern matches before the final LF, so the LF is lost ([subtitle-toolbox-php#1055](https://github.com/yama6a/subtitle-toolbox-php/issues/1055)) | the LF stays, after the closing mark and the trailing tags | #18 |
| a regional indicator or a flag followed by an Extend character or U+200D, such as U+1F1E9 U+0301, U+1F1E9 U+1F1EA U+0301 or U+1F1E9 U+1F3FD | `VisibleLength` and `countCharacters` count 2, because the `\X` of PCRE2 10.44 breaks there ([subtitle-toolbox-php#1056](https://github.com/yama6a/subtitle-toolbox-php/issues/1056)) | count 1, as rule GB9 of UAX #29 says | #18 |
| a letter that PHP and Go know in different Unicode versions, such as U+088F or U+10EC2 to U+10EC7 | `EmbedRightToLeft` finds no Arabic letter, because PCRE2 10.44 holds Unicode 15.0.0 | the letter counts, because the Go `unicode` tables are 17.0.0. A line whose only right-to-left letter is such a letter gets embedded | #18 |
| a value in format data outside null, bool, integer, float, string, list and object | PHP arrays can hold any value | `SetFormatData` rejects any Go type outside `nil`, `bool`, `int64`, `float64`, `string`, `[]any` and `*Data` | #12 |
| list of the file format data keys | only the cue has `getAllFormatData()` | `FormatDataKeys()` on `Subtitle` and on `Cue` | #12 |
| order of the format data keys | insertion order | sorted | #12 |
| cue data `alignment` that is not an integer, such as `"7"` | counts as a changed alignment, also for a bottom center cue | counts as missing, so as 2 | #12 |
| `Scale` or `SyncByPoints` result on a half millisecond in decimal, such as `Scale(1.5)` of 9 ms or `Scale(1.001)` of 500 ms | computes in seconds. A cue time rounds with `round($x, 3)`: 13 ms and 501 ms. A word timestamp rounds with `round($x * 1000)`: 13 ms and 500 ms | computes in `float64` milliseconds and rounds with `math.Round`: 14 ms and 500 ms, for cue times and word timestamps | #34 |
| `Shift`, or `SyncByPoints` with 1 point, by a fraction of a millisecond, such as `Shift(500*time.Microsecond)` of 1.001 s or `Shift(-500*time.Microsecond)` of 2.001 s | adds in binary seconds, so 1.001 + 0.0005 is 1.0014999999999998: 1.001 s and 2 s | adds exact nanoseconds and rounds half away from zero: 1.002 s and 2.001 s | #34 |
| a large number in the time limit message of a retiming, such as `Scale(1e300)` | `8.0E+300` | `8e+300` | #34 |
| a word timestamp that a retiming moves beyond 2562046:59:59.999, such as `Scale(10)` of `<2000000:00:00.000>` | writes the moved time `<20000000:00:00.000>` | writes `<2562046:59:59.999>`, the largest time that `WordTimestamp` reads | #34 |
| a shift or a sync point time that is NaN or infinite | `shift()` and `SyncPoint` throw an `InvalidArgumentException` | cannot occur, because a `time.Duration` is an integer | #34 |
| content that is blank after the control characters go, such as `\x01\n`, read in lenient mode | returns a new empty subtitle and drops the control character warning | returns an empty subtitle and keeps the warning | #14 |
| an append offset that is NaN or infinite | `append()` throws an `InvalidArgumentException` with "The append offset must be a finite number of seconds, got NAN." | cannot occur, because a `time.Duration` is an integer. `Append` has no offset message | #35 |
| a maximum gap of `removeDuplicateCues` or a time tolerance of `mergeSameTimeCues` that is NaN, infinite or negative | throws an `InvalidArgumentException` with "The maximum gap must be a finite number of 0 or more seconds, got -0.1." or "The time tolerance must be a finite number of 0 or more seconds, got -0.1." | NaN and infinity cannot occur. A negative value gives "The maximum gap must be 0 or more seconds, got -0.1." or "The time tolerance must be 0 or more seconds, got -0.1." | #35 |
| 2 cues with the same text and the same format data of 2 formats, stored in another order, such as `vtt` then `ass` and `ass` then `vtt` | `removeDuplicateCues` keeps both, because `===` compares the key order | `RemoveDuplicateCues` joins them, because the format data keys of a cue have no order | #35 |
| an encoding name outside the list of [encodings.md](encodings.md), such as `CP1125` | iconv reads it | `ReadOptions.Validate` fails with `The encoding "CP1125" is unknown.` | #16 |
| bytes that glibc iconv and the WHATWG tables of `golang.org/x/text` read differently, such as Big5 `87 40` | iconv decides | x/text decides. [encodings.md](encodings.md#differences-from-glibc-iconv) lists the bytes | #16 |
| the message of the decode warning and of invalid UTF-8 | names `ReadOptions::$encoding` | names no option: `Set the source encoding if that is wrong.` and `Set the source encoding of the file.` The CLI adds its own hint | #16 |
| library JSON metadata and format data keys | written in insertion order | written sorted, so the output does not depend on map order | #19 |
| `{}` and `[]` inside the data of one format in library JSON | both read as an empty array and write as `[]` | each keeps its type | #19 |
| `cues`, `lines` or `comments` as a JSON object with the keys `"0"`, `"1"` | reads as a list | `The field cues must be a list.` and the same for the others | #19 |
| a library JSON time of -100000 hours or less, such as `-1e20` | reads | `The field cues[0].start is not above -100000 hours.`, because `time.Duration` cannot hold it | #19 |
| library JSON that is not valid JSON | `The content is not valid JSON: Syntax error.` | the message of `encoding/json`, such as `The content is not valid JSON: unexpected end of JSON input.` | #19 |
| a float in library JSON format data, such as 1e25 or 1e-7 | `1.0e+25`, `1.0e-7` | `1e+25`, `1e-7`. A value from 1e-6 up to 1e21 is written without exponent, as `encoding/json` writes it | #19 |
| the block line of a library JSON warning | writes a float without fraction as `1`, a number such as `1e400` as `0`, and a metadata entry with the key `0` as a list | writes `1.0`, keeps the text `1e400`, and writes `{"0": value}` | #19 |
| a library JSON time that rounds to 100000 hours, such as `359999999.9996` | reads, and the cue time becomes 360000000 s | `The field cues[0].end is not below 100000 hours.`, because the bound applies after the rounding to whole milliseconds | #19 |
| a library JSON cue with a negative time that ends before it starts, such as start 5 and end -1 | reads as it is, because the order check needs both times at 0 or more | `The cue ends at -1 s, before it starts at 5 s.` Lenient mode swaps it | #19 |
| an empty cue identifier `""` in library JSON | written back as `""` | written as `null`, because an empty `Cue.ID` means no identifier | #19 |
